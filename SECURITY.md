# Security reporting

This public hosting snapshot is not a complete copy of the current production system. Passing repository checks does not constitute a security audit or approval for real-money trading. Sakura Rooms is a paper-only beta.

## Report privately

GitHub private vulnerability reporting is enabled for this repository. Use [Report a vulnerability](https://github.com/millw14/sakura-web/security/advisories/new) for sensitive reports. Keep exploit details, affected user data, credentials, and reproduction steps out of public issues.

An assigned responder and monitoring coverage have not yet been confirmed. Enabling the reporting form does not establish a response-time commitment. This policy does not promise a bounty or response deadline. Do not assume an email address is controlled or monitored by the project unless it is explicitly verified here.

Include the affected component, commit or deployed version if known, impact, and a minimal reproduction using your own test data. Remove secrets and unrelated personal information.

## Testing boundaries

Use local copies and accounts or infrastructure you control. This policy does not authorize probing the production website, testing other users' accounts, accessing their data, denial of service, or testing third-party services. Coordinate any shared-environment testing with its owner first.

Never submit production credentials, databases, private signing keys, operational backups, or private Studio source in a public issue, PR, or CI artifact.
